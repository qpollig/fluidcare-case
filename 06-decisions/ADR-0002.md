# ADR-0002. Слоистая архитектура: интерфейс → сервисы → репозиторий

**Статус:** принято

## Контекст

В прототипе окна интерфейса напрямую выполняли SQL. Сохранение записи с дренажами было неатомарным: при сбое могла остаться «половина записи».

## Решение

Интерфейс работает только с сервисами и неизменяемыми объектами передачи данных (DTO). Сервис управляет транзакцией, репозиторий отвечает только за доступ к данным.

## Рассмотренные альтернативы

- Оставить прямой доступ интерфейса к БД
- Перейти на веб-клиент

## Последствия

**Плюсы**

- Атомарное сохранение записи вместе с дренажами
- Предсказуемая иерархия доменных ошибок вместо сырых исключений БД
- Интерфейс можно тестировать без БД

**Цена**

- Больше кода и уровней абстракции
