# 03. Предметная область

**Вывод:** язык врача и язык системы разведены. Понятия ниже составляют единый язык: на нём формулируются требования, называются поля интерфейса и пишутся тесты. Технические понятия (транзакции, версии записей, роли БД) в него не входят.

## Доменная модель

```
Пациент ──1:N── Суточная запись ──1:N── Объём по дренажу ──N:1── Дренаж
   └──────────────────────────1:N───────────────────────────────────┘
Суточная запись: поступление (инфузия, энтерально) · потери (диурез, стул, рвота, зонд, дренажи)
```

Сущности, атрибуты и инварианты на уровне данных: [`04-data/`](../04-data/).

**Накопительный баланс** не хранится: это производная величина, сумма суточных балансов пациента по возрастанию даты. Поэтому он не может «разъехаться» с записями.

## Глоссарий

### Участники и случаи

| Понятие | Определение |
|---|---|
| Пациент | Человек на лечении в отделении. Идентифицируется ФИО и номером истории болезни |
| История болезни (ИБ) | Внутрибольничный номер, по которому врач находит пациента |
| Архивный пациент | Завершённый случай (выписка, перевод): только просмотр и экспорт, можно восстановить |

### Наблюдение

| Понятие | Определение |
|---|---|
| Суточная запись | Объёмы поступления и потерь жидкости у пациента за одну календарную дату |
| Поступление | Жидкость, полученная пациентом: инфузия и энтеральное поступление |
| Инфузия | Внутривенное введение жидкости |
| Энтеральное поступление | Жидкость через ЖКТ: питьё, питание, зонд на вход |
| Потери | Жидкость, вышедшая из организма: диурез, стул, рвота, сброс по зонду, дренажи |
| Диурез | Объём мочи |
| Стул, рвота | Потери, которые врач вводит числом или выбирает типичную категорию из подсказок |
| Сброс по зонду | Отделяемое по желудочному зонду |
| Дренаж | Установленный пациенту дренаж с названием; переиспользуется из записи в запись |
| Объём по дренажу | Отделяемое по конкретному дренажу за сутки |

### Расчёт

| Понятие | Определение |
|---|---|
| Суточный баланс | Поступление минус все потери за сутки |
| Накопительный баланс | Нарастающая сумма суточных балансов строго по возрастанию даты |

### Качество данных

| Понятие | Определение | Реакция системы |
|---|---|---|
| Необычное значение | Объём больше типичного | Сохранить можно после подтверждения |
| Недопустимое значение | Отрицательное или сверх жёсткой границы (вероятная опечатка) | Сохранить нельзя |
| Дубль даты | Две записи у пациента на одну дату | Новую не создать; старые подсвечиваются врачу |
| Конфликт правки | Запись изменили на другом ПК, пока её редактировали | Сохранение отклоняется, врач видит актуальную версию |

## Правила предметной области

1. У пациента не больше одной записи на дату.
2. Объёмы записываются в целых миллилитрах, не меньше нуля.
3. Суточный баланс = поступление − потери. Формула живёт в одном месте и меняется только по согласованию с врачом.
4. Накопительный баланс считается строго в хронологическом порядке.
5. Архивного пациента изменить нельзя.
6. Название дренажа уникально в пределах пациента.

> Числовые границы «необычного» и «недопустимого», а также значения подсказок для стула и рвоты согласованы с врачом и не публикуются.
