# 05. Требования (выборка)

**Вывод:** ниже ключевые требования версии 2.0 в том виде, в каком их получает разработка: user story, бизнес-правила и критерии приёмки в формате «Дано / Когда / Тогда». Каждый критерий проверяется автотестом.

---

## Функциональные требования

### FR-01. Ввод суточной записи

**Как** врач ОАР, **я хочу** ввести объёмы за сутки в форму, где поля уже разделены на поступление и потери, **чтобы** не относить каждый объём к столбцу вручную.

Правила:
- Поступление: инфузия, энтерально. Потери: диурез, стул, рвота, сброс по зонду, дренажи.
- Стул и рвоту можно ввести числом или выбрать типичную категорию из подсказок.
- Дренажей у записи может быть несколько; дренаж выбирается из установленных пациенту или добавляется новый.

Критерии приёмки:
- **Дано** открыта карточка пациента, **когда** врач нажимает «Добавить запись», **тогда** открывается форма с текущей датой и пустыми полями.
- **Дано** врач меняет любое поле, **когда** значение корректно, **тогда** суточный баланс внизу формы пересчитывается сразу, без сохранения.

### FR-02. Проверка значений

**Как** врач, **я хочу**, чтобы система ловила вероятные опечатки, **чтобы** ошибка ввода не попала в баланс.

Правила:
- Значение выше типичного порога считается **необычным**: подсветка и запрос подтверждения.
- Отрицательное значение или значение выше жёсткой границы считается **недопустимым**: сохранить нельзя.
- Пороги задаются в одном месте и согласуются с врачом.

Критерии приёмки:
- **Дано** в поле диуреза введено необычное значение, **когда** врач нажимает «Сохранить», **тогда** система просит подтвердить значение; после подтверждения запись сохраняется.
- **Дано** введено недопустимое значение, **когда** врач нажимает «Сохранить», **тогда** запись не сохраняется, а у поля показана причина.
- **Дано** врач исправил значение после предупреждения, **когда** сохраняет, **тогда** проверка выполняется заново.

### FR-03. Одна запись на дату

**Как** врач, **я хочу**, чтобы у пациента не появилось двух записей на одну дату, **чтобы** баланс за сутки не учитывался дважды.

Критерии приёмки:
- **Дано** у пациента есть запись на 12.03, **когда** врач создаёт ещё одну запись на 12.03, **тогда** сохранение отклоняется, ошибка показана у поля «Дата».
- **Дано** в старых данных есть дубли дат, **когда** врач открывает список пациентов, **тогда** у пациента видна плашка «Дубль даты».

### FR-04. Расчёт балансов

**Как** врач, **я хочу** видеть суточный и накопительный баланс и их динамику, **чтобы** оценивать потребность в инфузионной терапии.

Правила:
- Суточный баланс = поступление − потери.
- Накопительный = нарастающая сумма суточных по возрастанию даты; не хранится, а вычисляется.
- График накопительного баланса за 7 дней, 14 дней или весь период.

Критерии приёмки:
- **Дано** записи за 1, 2 и 3 число с суточными балансами +300, −100, +50 мл, **когда** врач открывает карточку, **тогда** накопительный баланс на 3 число равен +250 мл.
- **Дано** запись за 2 число изменена, **когда** изменение сохранено, **тогда** накопительный баланс пересчитан за все последующие даты.

### FR-05. Параллельная работа с нескольких ПК

**Как** врач, **я хочу**, чтобы правка коллеги на другом ПК не перезаписывалась моей, **чтобы** данные пациента не терялись.

Критерии приёмки:
- **Дано** врачи А и Б открыли одну запись, **когда** А сохранил изменения, а затем Б пытается сохранить свои, **тогда** Б видит сообщение «Запись изменена на другом компьютере» и актуальную версию, а изменения А не потеряны.

### FR-06. Архив

**Как** врач, **я хочу** переносить завершённые случаи в архив, **чтобы** список текущих пациентов оставался коротким, а история сохранялась.

Критерии приёмки:
- **Дано** пациент в архиве, **когда** врач открывает его карточку, **тогда** доступны только просмотр и экспорт; кнопки изменения неактивны.
- **Дано** пациент в архиве, **когда** врач нажимает «Восстановить», **тогда** пациент возвращается в список текущих.

### FR-07. Экспорт

**Как** врач, **я хочу** выгрузить баланс пациента в PDF, CSV или TXT, **чтобы** перенести его в медицинскую карту или передать коллегам.

## Нефункциональные требования

| ID | Требование | Как проверяется |
|---|---|---|
| NFR-01 | Персональные данные (ФИО, номер ИБ) не попадают в журналы приложения | Автотест-«страж» ищет тестовые ФИО и номер ИБ в логах |
| NFR-02 | Интерфейс не блокируется при обращении к БД | Операции с БД выполняются в фоне |
| NFR-03 | Любое изменение данных фиксируется: кто, когда, с какого ПК, что было и что стало | Журнал на триггерах БД, программа не может его изменить |
| NFR-04 | Пароль к БД не хранится открытым текстом | Шифрование средствами ОС на уровне машины |
| NFR-05 | Работа в закрытой сети больницы без доступа в интернет | Все компоненты локальные |
| NFR-06 | Потеря связи с сервером БД видна врачу сразу | Индикатор связи в верхней панели |
| NFR-07 | Установка на рабочий ПК без Python и ручной настройки | Установщик + команда самопроверки |
| NFR-08 | Формула баланса существует в одном месте | Архитектурный тест: UI и экспорт не считают баланс сами |
